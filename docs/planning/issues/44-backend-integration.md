## Question

如何用真实后端证明登录、查询与维护流程按既有契约工作，并核实模拟测试无法断言的后端行为？

## Parent

[实现 Orbit Admin 首版前端脚手架](11-first-release-spec.md)。本票落实真实环境联调，不修改后端。

## What to build

后台工作人员的登录、刷新恢复、失效与退出在真实后端上验证通过；管理端账号、字典与参数的查询和写入在获准环境与测试数据上验证，并单独核实参数列表可选筛选的后端校验行为。

## Acceptance criteria

- [ ] 【未验收】使用获准的环境与测试数据，真实联调登录、刷新恢复、认证失效与退出，包括当前管理端账号接口的实际鉴权行为。（阻碍：本地网关 18080 及微服务未运行，未提供获准联调账号凭据）
- [ ] 【未验收】真实联调管理端账号的查询与新增，以及身份与状态的完整字典。（阻碍：后台微服务未运行，未提供获准测试数据）
- [ ] 【未验收】真实联调字典类型、字典项、参数的查询、新增与编辑，并单独核实参数列表可选筛选的后端校验行为；不以源码或模拟测试断言其可用，环境不可用时记录未验收与阻碍，不擅自改后端或缩减规格。（阻碍：后台微服务未运行，未提供获准测试数据；参数列表 GET 存在 DTO @NotBlank 与控制器缺少 @Validated 的待测核验点）
- [x] 【已验证】核实整体导航、默认页、404、重新进入页面的默认状态、认证失效时的表单清理与不重放写请求在不同模块间一致，不残留占位导航或虚构统计。
