## Question

如何让后台工作人员查询并维护参数，确保多行参数值不被自动转换或格式化？

## Parent

[实现 Orbit Admin 首版前端脚手架](11-first-release-spec.md)。本票落实参数导航及查询、新增、编辑。

## What to build

后台工作人员通过参数导航筛选和分页浏览配置，以弹窗新增或编辑参数，普通多行文本值原样提交。

## Acceptance criteria

- [ ] `GET /argument/list` 使用 pageNo、pageSize、可选 configKey 和 name；编码精确、名称包含筛选。展示编码、名称、值、备注及操作，长文本可完整查看。
- [ ] 解析 totals、totalPages、list；页面管理页码和页大小，默认 10 条，可选 20、50。点击查询或回车应用筛选，查询或改变页大小回第一页；重置清空并重新查询，重新进入页面恢复默认状态。
- [ ] 区分加载、暂无数据、失败并提供重试；连续查询只接受最新响应，失败不将旧结果冒充新结果。
- [ ] 新增 `POST /argument/add`，编辑 `POST /argument/edit`，提交 configKey、name、value、可选 remark；编辑编码只读。不提供删除。
- [ ] 编码、名称和值必填且拒绝全空白，不增加契约外字符集或长度上限；值使用普通多行文本，原样提交，包括有效文本中的空白和换行，不自动解析或格式化。
- [ ] 新增、编辑用弹窗；提交中防重复且禁止关闭，明确失败保留输入且仅反馈一次；成功关闭并刷新，新增回第一页、编辑保留当前页。
- [ ] 写入成功但列表刷新失败分别说明；写入结果不确定保留输入、解除锁定并提示先查询核实，不自动重试。
- [ ] 脏表单取消、关闭及站内导航需确认；未修改直接关闭，认证失效直接清理；不增加跨页面缓存、表单持久化或浏览器关闭拦截。
- [ ] 使用统一主题和说明栏；人工验证窄视口、长文本、键盘填写、弹窗焦点循环及恢复。
- [ ] 在真实页面入口和 HTTP 边界测试查询字段、分页、重置、最新响应、失败恢复、只读编码、全空白校验、多行值原样提交及表单写入异常行为。
- [ ] 真实联调时单独核实 GET 可选筛选的后端校验行为；不能以源码或模拟测试断言其已可用。环境不可用时记录未验收及阻碍，不擅自改后端或缩减规格。
