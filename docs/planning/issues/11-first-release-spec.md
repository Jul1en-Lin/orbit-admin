## Question

如何依据已经确认的规划决策，实现可运行、可复制复用、可独立部署的 Orbit Admin 首版，并通过本地自动检查及真实后端人工验收？

## Problem Statement

后台工作人员需要通过统一的中文管理界面登录现有 Framework-Java 后端，维护管理端账号、字典与参数。目前仓库只有规划文档和可丢弃视觉原型，没有可使用的正式前端应用。直接从接口搭页面容易误用内部接口、承诺后端不支持的操作，或遗漏会话失效、写入结果不确定等关键交互。

项目维护者还需要一个能够复制后独立开发的前端脚手架，具备明确的模块边界、统一视觉、本地质量检查和独立部署方式，而不要求改造现有后端。

## Solution

交付中文、桌面优先的 Orbit Admin 首版：登录后进入管理端账号页，通过顶部静态导航访问管理端账号、字典和参数。采用已选定的深墨绿顶栏分栏工作台，提供一致的查询、分页、弹窗表单及异常反馈。

所有功能受现有后端契约约束。浏览器通过同源代理访问网关，前端与后端分别构建和部署。交付包括应用、关键行为测试、本地统一检查、开发与部署说明及验收记录。自动检查、真实后端联调和上线部署验证分别记录，不以构建成功或模拟请求通过代替实际验收。

## User Stories

### 登录与会话

1. 作为后台工作人员，我希望使用手机号和密码登录，以便访问现有后台业务。
2. 作为后台工作人员，我希望通过回车提交登录且提交期间不重复发送请求，以便顺畅登录。
3. 作为后台工作人员，我希望登录失败时看到一次明确反馈并保留输入，以便修正后重试。
4. 作为后台工作人员，我希望刷新当前标签页后恢复登录状态，以便继续工作。
5. 作为后台工作人员，我希望会话恢复时先看到加载状态，以便不会在身份尚未确认时操作业务页面。
6. 作为后台工作人员，我希望恢复会话遇到网络或服务异常时能够重试或返回登录，以便不会被错误判定为认证失效。
7. 作为后台工作人员，我希望登录后返回原先访问的有效站内页面，以便继续此前任务。
8. 作为后台工作人员，我希望没有回跳目标时进入管理端账号页，以便直接开始工作。
9. 作为后台工作人员，我希望多个请求同时认证失效时只收到一次提示并返回登录，以便避免重复打断。
10. 作为后台工作人员，我希望重新登录后旧请求不会清除或覆盖新会话，以便登录状态保持正确。
11. 作为后台工作人员，我希望会话失效后不自动重放新增和修改操作，以便避免意外重复写入。
12. 作为后台工作人员，我希望退出时清除本地会话和页面数据，以便结束当前标签页的使用。
13. 作为后台工作人员，我希望密码不被持久化或写入日志，离开登录页后清除，以便减少不必要的暴露。

### 导航与视觉

14. 作为后台工作人员，我希望顶部展示品牌、当前导航、当前管理端账号昵称和退出入口，以便确认位置及登录身份。
15. 作为后台工作人员，我希望通过固定导航访问管理端账号、字典和参数，以便快速找到首版功能。
16. 作为后台工作人员，我希望页面采用一致的深墨绿、暖白、橙色及细边框，以便获得统一的工作体验。
17. 作为后台工作人员，我希望表格、筛选和表单使用清晰的正文字体，以便阅读密集业务内容。
18. 作为后台工作人员，我希望说明栏展示当前页面的操作边界，以便了解现有接口支持的能力。
19. 作为后台工作人员，我希望窄视口下说明栏下移、表格可横向滚动且主要操作可达，以便窗口缩小时仍能完成任务。
20. 作为后台工作人员，我希望仅用键盘也能导航、查询、选择选项和填写提交弹窗，以便不依赖鼠标。
21. 作为后台工作人员，我希望焦点清晰可见且关闭弹窗后回到触发入口，以便继续键盘操作。
22. 作为后台工作人员，我希望未知页面显示 404 并提供返回默认页入口，以便从无效链接恢复。

### 通用列表与表单

23. 作为后台工作人员，我希望点击查询或按回车才应用筛选，以便先完整填写查询条件。
24. 作为后台工作人员，我希望重置清空筛选并重新查询，以便回到默认结果。
25. 作为后台工作人员，我希望分页列表默认每页 10 条并可切换为 20 或 50 条，以便控制阅读密度。
26. 作为后台工作人员，我希望查询或修改每页条数时回到第一页，以便不会停留在无效页码。
27. 作为后台工作人员，我希望能区分加载、暂无数据和请求失败，以便判断当前页面状态。
28. 作为后台工作人员，我希望请求失败时留在当前页面并能重试，以便不丢失操作上下文。
29. 作为后台工作人员，我希望连续查询只展示最新一次请求的结果，以便旧响应不会覆盖新条件。
30. 作为后台工作人员，我希望重新查询失败时不把旧数据当作新结果展示，以便不会误读数据。
31. 作为后台工作人员，我希望新增和编辑采用一致的弹窗，以便学习一次交互后能用于各页面。
32. 作为后台工作人员，我希望必填和格式错误在提交前得到提示，以便修正无效输入。
33. 作为后台工作人员，我希望提交期间不能重复提交或关闭弹窗，以便避免重复操作。
34. 作为后台工作人员，我希望明确提交失败时保留表单且只提示一次，以便修改后重试。
35. 作为后台工作人员，我希望保存成功后关闭弹窗并刷新列表，以便查看最新数据。
36. 作为后台工作人员，我希望新增后回第一页、编辑后保留当前页，以便按既定规则继续浏览。
37. 作为后台工作人员，我希望写入成功但列表刷新失败时能区分两者，以便不会误以为需要再次保存。
38. 作为后台工作人员，我希望写请求结果不确定时被提醒先查询核实，以便避免盲目重复写入。
39. 作为后台工作人员，我希望有未提交修改时取消、关闭或站内导航需要确认，以便避免意外丢失输入。
40. 作为后台工作人员，我希望未修改的表单能直接关闭，以便减少无意义确认。
41. 作为后台工作人员，我希望长文本能够完整查看，以便不因截断遗漏业务内容。
42. 作为后台工作人员，我希望重新进入页面时使用默认查询状态，以便页面行为可预测。

### 管理端账号

43. 作为后台工作人员，我希望查看管理端账号的 ID、手机号、昵称、身份、状态和备注，以便了解现有管理端账号。
44. 作为后台工作人员，我希望按 ID、手机号、状态精确筛选管理端账号，以便定位目标记录。
45. 作为后台工作人员，我希望管理端账号列表按实际非分页接口展示，以便不会出现无效分页或排序功能。
46. 作为后台工作人员，我希望填写手机号、密码、昵称、身份、状态及可选备注新增管理端账号，以便接入新的工作人员。
47. 作为后台工作人员，我希望身份和状态来自完整的后端字典选项且由我主动选择，以便不会默认赋予身份或漏掉候选项。
48. 作为后台工作人员，我希望字典选项加载失败时能重试且不能提交依赖选项的表单，以便不会提交虚构编码。
49. 作为后台工作人员，我希望列表遇到未知编码仍显示原始编码和记录，以便发现数据差异而不丢失信息。
50. 作为后台工作人员，我希望页面只提供首版支持的列表、筛选和新增，以便不会误用编辑、重置密码或停用能力。

### 字典与参数

51. 作为后台工作人员，我希望按编码精确筛选、按名称前缀筛选字典类型，以便找到需要维护的类型。
52. 作为后台工作人员，我希望查看字典类型的编码、名称、状态、备注及可用操作，以便识别类型及维护入口。
53. 作为后台工作人员，我希望新增和编辑字典类型的名称、备注，且编辑时编码只读，以便遵守现有定位规则。
54. 作为后台工作人员，我希望从所属字典类型进入字典项页并看到所属类型，以便明确维护范围。
55. 作为后台工作人员，我希望按名称前缀筛选字典项并查看编码、名称、排序、状态、备注，以便找到目标字典项。
56. 作为后台工作人员，我希望新增字典项时填写编码、名称及可选整数排序、备注，以便维护该类型的选项。
57. 作为后台工作人员，我希望编辑字典项时编码只读、所属类型固定，以便不会提交后端不支持的变更。
58. 作为后台工作人员，我希望清空字典项已有备注时被明确告知接口限制，以便不会误认为清空已生效。
59. 作为后台工作人员，我希望返回字典类型时恢复默认筛选和第一页，以便按照统一页面状态规则继续工作。
60. 作为后台工作人员，我希望按编码精确筛选、按名称包含筛选参数，以便查找配置。
61. 作为后台工作人员，我希望查看参数的编码、名称、值和备注，以便了解现有配置内容。
62. 作为后台工作人员，我希望新增和编辑参数时使用多行文本填写值且原样提交，以便不被自动解析或格式化改变内容。
63. 作为后台工作人员，我希望编辑参数时编码只读且编码、名称、值不能全为空白，以便符合既有契约。
64. 作为后台工作人员，我希望字典和参数不显示删除或字典状态开关，以便不会尝试未支持的写操作。

### 开发、复用与部署

65. 作为项目维护者，我希望使用固定版本的运行时、包管理器和依赖锁文件，以便复现安装与构建。
66. 作为项目维护者，我希望一个本地命令完成格式、Lint、类型、测试和构建检查，以便统一交付门槛。
67. 作为项目维护者，我希望按业务聚合代码并明确共享能力边界，以便复制模板后独立开发。
68. 作为项目维护者，我希望统一请求层负责认证和响应契约，以便页面不会各自实现会话失效规则。
69. 作为项目维护者，我希望本地与生产使用一致的同源 API 路径语义，以便减少部署时的接入差异。
70. 作为项目维护者，我希望静态前端与后端分别部署且不要求生产持续运行 Node，以便独立管理构建产物。
71. 作为项目维护者，我希望刷新深层页面时正常加载应用，而 API 和缺失静态资源不返回页面，以便正确区分请求类型。
72. 作为项目维护者，我希望验收记录明确已通过和未验收项目，以便不会把规划完成当作应用交付完成。

## Implementation Decisions

### 技术与模块边界

- 使用 Vue 3、Vite、TypeScript、Vue Router、Pinia、Axios、SCSS 和 Element Plus。Node 采用 24 系列；实现时核实依赖兼容性、固定具体补丁版本，以 packageManager 固定 pnpm 版本并提交锁文件。
- 按管理端账号、字典、参数聚合页面、专属组件、业务接口和类型；布局、认证、通用基础能力独立。业务模块提供明确对外入口，不跨模块引用页面和内部组件。
- 直接使用 Element Plus 表格、表单、输入框、下拉框和弹窗；自写顶栏、页面框架、标题区及说明栏。不建设万能表格、配置式表单或纯转发包装。真实复用出现后才提取共享能力。
- Pinia 仅保存跨页面共享状态，如登录会话。查询、分页及未提交表单位于页面内部；不做跨页面列表缓存或表单持久化。
- 统一请求层负责认证头、响应解包和统一 401；业务接口层负责调用、请求与返回类型及必要转换；页面负责加载、成功反馈和业务失败交互。同一次失败只提示一次。
- 不修改后端数据库结构，不新增后端接口，不把前端隐藏入口视为权限安全边界。

### 登录与会话契约

- 登录使用 `POST /sys_user/login/password`，JSON 字段为 phone、password；手机号直接提交，密码按 UTF-8、AES-128/ECB/PKCS5Padding、Hex 输出兼容后端。JavaScript 使用与该 AES 块大小兼容的 PKCS#7 填充，以 Java 可信样例验证。该转换只用于登录契约，不擅自应用于新增管理端账号密码。
- 登录表单仅校验手机号、密码非空；不新增手机号格式、密码强度或长度约束，不自动去除密码空格。密码不持久化、不写日志，离开登录页清除。
- 固定浏览器加密密钥不提供可靠保密性、不替代 HTTPS；实际密钥或凭据不写入规划文档与日志，服务端秘密不放入浏览器可见配置。
- 登录返回 accessToken 和 expires；expires 是毫秒时长，不是时间戳。使用 sessionStorage 保存 accessToken，以 `Authorization: Bearer <accessToken>` 发送认证信息，不提供记住我。
- 登录成功与刷新恢复均先获取 `GET /sys_user/login/get_info`，初始化当前管理端账号后才加载业务页面。恢复时有加载状态；认证失效清理会话，网络或服务端异常保留令牌并提供重试与返回登录。
- 多个当前会话请求并发 401 时只清理、提示和跳转一次；保留原有效站内目标，不保留密码或未提交表单，不自动重放写请求。旧会话请求不得覆盖或清除新会话。
- 登录接口自身错误留在登录表单，不走会话过期跳转。回跳只接受有效站内路由，拒绝外部目标；无目标进入管理端账号页。
- 不以前端倒计时或轮询续期决定失效，以服务端认证结果为准。退出仅清除本地令牌、当前管理端账号与页面数据并返回登录；不调用 C 端退出接口，不宣称服务端令牌已撤销。

### 接口与数据边界

以下均为 service-local HTTP 路径，不是浏览器直连地址；通过统一代理接入网关。完整字段、VO、校验与源码证据链接见 Further Notes。

| 能力 | 契约与限制 |
| --- | --- |
| 管理端账号列表 | `POST /sys_user/list`；JSON 可选 userId、phoneNumber、status，均精确匹配；返回数组，不分页。 |
| 新增管理端账号 | `POST /sys_user/add_edit`；不传 userId；identity、phoneNumber、password、nickName、status 必填，remark 可选。密码为 1–20 位英文字母或数字；不调用编辑分支。 |
| 字典类型 | `GET /dictionary_type/list`，query 为 pageNo、pageSize、typeKey、value；typeKey 精确、value 前缀。`POST /dictionary_type/add` 和 `/dictionary_type/edit` 提交 typeKey、value、可选 remark；编辑按 typeKey 定位，编码只读。 |
| 字典项 | `GET /dictionary_data/list`，query 为固定 typeKey、可选 value、pageNo、pageSize；value 前缀，遵循后端 sort、id 升序。新增 `POST /dictionary_data/add` 提交 typeKey、dataKey、value、可选 sort 和 remark；编辑 `POST /dictionary_data/edit` 提交 dataKey、value、可选 sort 和 remark，不发送可变所属类型。 |
| 参数 | `GET /argument/list`，query 为 pageNo、pageSize、可选 configKey 和 name；configKey 精确、name 包含。`POST /argument/add` 和 `/argument/edit` 提交 configKey、name、value、可选 remark；编辑编码只读。 |

- 响应包裹为 code、msg、data，成功码为 200000；写操作 data 为记录 ID。分页 data 仅含 totals、totalPages、list，不包含当前页码和页大小。页码与页大小由前端管理，不凭空增加后端分页字段或排序能力。
- 错误按 HTTP 状态及业务 code 分类，不依赖中文消息文本作为机器契约。既有部分业务失败返回 HTTP 500，仍在当前页面提供反馈，不整页跳转错误页。
- 管理端账号展示 ID、手机号、昵称、身份、状态和备注。身份选项来自 typeKey=admin，状态选项来自 typeKey=common_status 的字典项列表，以 dataKey 提交、value 展示；完整拉取所有分页，不硬编码候选、不调用内部 Feign 接口。
- 身份与状态必须主动选择，不默认赋予身份。选项加载失败可重试，阻止提交依赖这些选项的新增表单。未知编码展示原始值，不丢弃记录。字典记录的数值 status 与管理端账号的字符串 status 不混用。
- 字典类型展示编码、名称、状态、备注及操作；字典项展示编码、名称、排序、状态、备注及操作。字典项页显示所属类型并提供返回类型入口；返回后恢复默认筛选和第一页。
- 字典类型、字典项和参数的编码、名称拒绝全空白，不自行添加字符集或长度上限。字典项排序选填，有值时为整数，不限定正数。类型与项均不提供状态写入。
- 字典项编辑不能清空已有备注：阻止提交并提示“当前接口不支持清空备注”；可改为其他非空内容，不以空格绕过。编辑接口仅更新非 null 的排序，不承诺将已有排序清空为 null。
- 参数展示编码、名称、值、备注及操作；值为普通多行文本，必填且不能全空白，原样提交，不自动解析或格式化。
- 参数列表筛选按可选实现，但其 GET 校验行为仍需真实联调确认，不将源码推断当作已验证事实。

### 查询与写入交互

- 点击查询或回车应用筛选；重置清空并重新查询。分页列表查询或改变每页条数后回第一页；默认 10 条，可选 20、50 条。管理端账号无分页，不提供未支持的排序。
- 初次加载、成功空结果和失败须区分；空结果显示“暂无数据”，失败显示错误与重试入口。重新查询失败不得将旧结果当新结果，连续查询只接受最新一次响应。
- 新增、编辑统一弹窗；提交期间防重复且禁止关闭。失败保留输入、只提示一次；明确成功才关闭并刷新列表，新增回第一页、编辑留当前页，不保证新增记录排序到第一页。
- 写入成功但刷新失败时明确分别反馈，不能诱导重复保存。超时等未收到明确响应的写入保留表单，提示“提交结果未确认，请先查询核实”，解除提交锁定但不自动重试；不承诺绝对防重复写入。
- 修改过的表单在取消、关闭或站内导航时确认放弃；未修改直接关闭。认证失效直接清理，不保留表单，不添加浏览器关闭拦截。

### 布局、主题与路由

- 采用 B 顶栏分栏工作台：顶部品牌、当前导航、当前管理端账号昵称和退出；主区为业务内容，右侧说明栏仅说明当前操作边界，不展示虚构统计。窄视口说明栏下移，表格可横向滚动，表单与主要操作可达。
- 深墨绿背景、暖白正文、橙色主操作、细线分区、衬线标题；表格、表单、筛选使用无衬线字体，以可读性优先，不要求逐像素复制原型。
- 集中维护颜色、字体、间距、边框及交互状态，并映射到 Element Plus；全局主题覆盖下拉、弹窗等浮层，局部样式只负责页面布局，不各自覆盖组件库内部样式。
- 静态导航为管理端账号、字典、参数；默认管理端账号页，不新增仪表盘。未知路由显示 404 和返回默认页入口；请求失败留在当前页，无缺少权限模型支撑的 403 流程。
- 键盘可完成导航、查询、下拉选择、弹窗填写与提交；焦点可见，弹窗焦点循环及关闭后的焦点恢复必须实测。

### 工程与部署交付

- TypeScript strict，使用 vue-tsc、ESLint、Prettier；格式、零警告 Lint、类型、测试和生产构建由一个本地统一命令执行。冻结锁文件安装，依赖升级独立进行并重跑检查。
- 浏览器同源使用 `/api`；本地 Vite 代理与生产 Nginx 保持一致路径语义，将 `/api` 替换为网关 `/admin`，由网关 StripPrefix=1 转发至 admin service。例如 `/api/sys_user/login/password` 对应网关 `/admin/sys_user/login/password`。
- 本地候选网关为 `http://127.0.0.1:18080`，配置依据已核实，服务运行与完整链路尚未验证。Nacos 是配置中心，不是 API upstream；生产网关目标部署时另行核实，不绕过网关直连业务服务。
- 前端在站点根路径部署，Router history 模式；Nginx 托管静态构建产物并代理 API。页面路由可回退应用入口，API 和缺失静态资源不得回退 HTML。生产无需持续运行 Node 提供前端页面。
- 前后端同机、同次上线但分别构建与部署。本地先启动后端并联调，上云后再验收部署链路；本规格不授权修改共享基础设施或实际发布。
- 采用构建时配置，不新增运行时配置加载机制。浏览器可见配置视为公开信息；后端地址由开发代理和 Nginx 配置，不提交服务端秘密。
- 交付开发启动、配置、检查、复制复用和部署说明，以及实际浏览器版本和验收状态。规划完成、自动检查通过、真实联调通过、上线部署通过应分别表述。

## Testing Decisions

用户已在本会话确认以下测试边界。仓库尚无正式应用测试，既有视觉原型的人工脚本检查仅提供场景参考，不是可复用测试套件，也不代表真实组件验收通过。

### 主要自动化边界

- 使用 Vitest + Vue Test Utils + jsdom，从页面或应用入口挂载真实组件、路由、Pinia 和请求层，只在 HTTP 边界模拟响应。不另建完整模拟后端，不通过大量模块 mock 绕过被测行为。
- 以工作人员可观察的结果和对外请求契约为断言：界面、导航、反馈次数、请求字段及发送次数。避免断言私有方法、组件内部状态、CSS 内部结构或 Element Plus 实现细节。
- 测试集中在根目录 tests/，按业务结构组织，使用 *.test.ts，共用初始化也集中存放。不设覆盖率百分比，不使用大面积快照，不引入浏览器端到端自动化。

### 关键自动化场景

- 认证与应用入口：登录校验和防重复提交；首次登录、刷新恢复；当前管理端账号初始化前的加载；恢复时网络失败保留令牌且能重试；有效站内回跳与外部目标拒绝；本地退出。
- 会话并发：多个 401 只提示与跳转一次；旧会话响应不覆盖或清除新会话；登录自身错误不触发过期流程；失效后不重放写请求。
- 请求契约与转换：认证头、成功包裹、失败分类、管理端账号数组与分页 VO 差异、筛选字段和分页参数、仅新增时不传 userId、完整分页选项及未知编码回显。通过页面发出的 HTTP 请求和渲染结果验证，不为每层重复同一测试。
- 关键页面：成功、加载、空数据、失败重试、重置、分页、仅接受最新查询结果、重新查询失败不误呈现旧结果。
- 关键表单：必填与具体约束、编码只读、所属类型固定、依赖选项加载失败、已有字典项备注禁止清空、参数值原样提交；提交成功与失败、重复提交防护、脏表单放弃确认及提交中关闭限制。
- 写入结果：成功后刷新与页码规则，写入成功但刷新失败的独立提示，结果不确定保留表单且不自动重试。
- 页面与组件行为在相同高层边界测试，不为每个字段建立额外测试接口；真实浏览器的视觉、布局和焦点表现交人工验收。

### 必要的独立兼容测试

- 登录密码转换以 Java 侧可信样例核对 UTF-8、填充和 Hex 输出，测试公共转换输入输出而非加密库内部实现。样例尚未准备，实施时建立非真实密码的测试向量，不在记录中披露实际密钥或凭据。

### 人工验收与通过标准

- 实现阶段首批即使用真实 Element Plus 验证主题、浮层、可见焦点、下拉键盘操作、弹窗焦点循环和关闭后恢复；严重问题才重开选型，不重新横向比较组件库。
- 桌面 Chrome、Edge 当前稳定版，记录实际版本；覆盖中文布局、长文本、窄视口内容可达性及键盘完成主要任务。
- 真实后端验证登录、会话恢复与失效、管理端账号新增和查询、字典类型/项及参数的查询、新增和编辑。写操作使用获准的测试数据及环境，不修改后端或擅自清理共享数据。
- 核实本地后端启动与依赖连通、代理前缀、认证头、实际 get_info 鉴权行为、参数可选筛选；上线准备阶段核实生产 upstream、页面路由刷新、API 与缺失资源不回退页面、域名及 HTTPS 接入。
- 交接须运行冻结锁文件安装及完整本地检查，并逐项记录人工结果。环境不可用、实际操作未执行或部署尚未进行时标记“未验收”及阻碍，不以模拟测试替代，不宣称首版已完整交付。
- 先例依据为已确认的工程门槛、页面验收规则、组件选型与视觉原型人工检查，均通过下方链接追溯。

## Out of Scope

- C 端用户管理；管理端账号编辑、删除、重置密码与停用操作。
- 字典类型、字典项、参数删除，字典状态修改，字典项迁移所属类型及编辑编码。
- 图片验证码、注册、找回密码、记住我、服务端主动退出、前端刷新令牌及轮询续期。
- 完整 RBAC、角色管理、动态菜单、按钮权限及没有权限模型支撑的 403 流程。
- 后端改造、新接口、数据库结构变更、后端幂等能力或绝对防重复写入保证。
- 仪表盘、虚构统计、跨页面列表缓存、未提交表单持久化及浏览器关闭拦截。
- 国际化、多主题切换、多标签页、专门移动端体验、完整无障碍认证；Firefox 和 Safari 不作为首版验收目标。
- 万能表格、配置式表单、CLI 生成器、共享组件包、模板自动升级及多组件库混用。
- Git hooks、commitlint、远程 CI、自动发布、依赖升级机器人、浏览器端到端自动化和完整模拟后端。
- 参考网站品牌、插画和内容复制；将个人学习首版描述为已通过生产安全认证。功能优先不意味着取消认证、暴露秘密或宣称接口安全。
