## Question

如何在刷新、认证失效和并发请求下维持正确会话，并让后台工作人员返回有效的站内目标？

## Parent

[实现 Orbit Admin 首版前端脚手架](11-first-release-spec.md)。本票落实会话恢复、失效、回跳及错误路由。

## What to build

刷新标签页后恢复当前管理端账号；网络故障允许重试，真正认证失效时统一返回登录。重新登录后的会话不受旧请求干扰，未知页面提供明确的恢复入口。

## Acceptance criteria

- [ ] 从 sessionStorage 恢复令牌，取得当前管理端账号前展示加载，不加载业务页面。
- [ ] 恢复遇到网络或服务异常时保留令牌，提供重试及返回登录；认证失效才按失效流程清理。
- [ ] 当前会话多个并发 401 只清理、提示、跳转一次；清除当前管理端账号及页面数据，不保存未提交表单，不重放新增或修改请求。
- [ ] 请求归属旧会话时，无论成功还是失败都不得覆盖或清除新会话；退出后的迟到响应不得恢复旧会话。
- [ ] 登录接口自身错误留在登录表单，不触发会话过期跳转。其他请求失败仍按 HTTP 状态和业务 code 分类，同一次失败只反馈一次。
- [ ] 未登录访问及认证失效保留有效站内目标；登录后回跳，仅允许有效站内路由，拒绝外部目标，无目标进入管理端账号页。
- [ ] expires 按毫秒时长理解；不以前端倒计时决定失效，不轮询续期，不新增刷新令牌机制。
- [ ] 未知路由显示 404 并提供返回默认页入口，不引入无权限模型支撑的 403 流程。
- [ ] 从应用入口与 HTTP 边界验证恢复成功、恢复失败重试、有效和非法回跳、并发失效、旧响应隔离、退出及写请求不重放；断言界面、导航和请求次数，不断言内部状态结构。

## Delivery notes

复用前置工单建立的真实组件、路由、Pinia 和请求层测试方式，不新增底层 mock 测试体系。业务页面尚未完成时可用受保护的工作台入口验证会话行为；真实 get_info 鉴权仍须人工联调核实，不把网关白名单推断当成实测结论。
