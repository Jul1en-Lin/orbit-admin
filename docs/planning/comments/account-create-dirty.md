# 脏表单确认与失效清理

## Resolution

已落实管理端新增账号表单的脏状态追踪、多途径关闭/导航确认防丢机制，以及会话失效时的即时清理与防重放约束：

- 脏状态追踪：
  - 完整追踪表单六项可编辑字段（`identity`、`phoneNumber`、`password`、`nickName`、`status`、`remark`）。
  - 若任一字段偏离初始空白状态，即判定为脏表单（`isCreateFormDirty` 为 `true`）；若用户未输入或输入后清空回到初始空白状态，判定为未修改表单（clean）。
- 未修改表单（clean）：
  - 点击取消按钮、右上角关闭按键（X）、遮罩层点击（overlay）、ESC 按键或站内路由导航（`onBeforeRouteLeave`）时，直接关闭弹窗或放行导航，不打扰工作人员。
- 修改过的脏表单（dirty）：
  - 在点击取消按钮、右上角关闭按键、遮罩层、ESC 按键或尝试通过站内路由离开当前页面时，触发二次确认拦截提示「表单有未保存的修改，确定放弃吗？」。
  - 工作人员取消确认时：弹窗继续保持开启，所有已录入数据与状态完整保留；站内路由导航被取消，停留在当前账号页。
  - 工作人员确认放弃时：清空已录入数据并重置表单状态，关闭弹窗或放行路由导航。
- 认证失效清理与防重放：
  - 遇到 401 认证失效（包括提交表单时接口返回 401、后台请求触发 401 或手动调用 `auth.signOut()` 时），即时关闭新增弹窗并丢弃未提交的表单数据。
  - 认证失效触发的登录页重定向不弹出脏表单确认提示，无阻碍平滑跳转。
  - 重新登录后，新增弹窗处于关闭状态，表单恢复初始空白，绝不重放新增或写请求。
- 隔离与无副作用约束：
  - 严格不增加任何浏览器窗口级别关闭拦截（无 `beforeunload` 监听器）。
  - 未提交表单数据仅存在于组件内存响应式状态中，绝不写入 `localStorage` 或 `sessionStorage`。
- 自动化测试覆盖：
  - 新增 `tests/account-create-dirty.test.ts`（共 17 个自动化测试场景），全面覆盖：
    * 未修改表单在取消按钮、关闭 X、ESC 按键、遮罩层及站内导航下无提示直接关闭与离开；
    * 录入后清空场景下的无提示直接关闭；
    * 修改过的表单在取消按钮、关闭 X、ESC 按键、遮罩层点击及站内路由导航时的确认拦截、取消保留数据与确认清空关闭；
    * 六个表单字段逐一修改时的脏状态敏感性；
    * 提交时 401 响应的弹窗清理、跳转无阻碍、数据不落盘与重新登录后零写请求重放；
    * 后台 401 及主动 signOut 时的表单即时清理；
    * 无 `beforeunload` 监听注册与 Web Storage 零持久化断言。
- 质量检查：
  - 全套代码与质量门槛全部通过：`npm run check`（Prettier 格式检查、ESLint 零警告、vue-tsc 严格类型检查、Vitest 12 个测试套件 88 项测试全数通过、Vite 生产构建成功）。
