# 确定登录与会话失效交互 · 讨论记录

## 已确认：登录持久性、回跳与失效

用户对以下四项推荐回复「可以 继续」：

- accessToken 存入 sessionStorage，支持当前标签页刷新恢复；首版不提供「记住我」。该存储仍可被同源脚本读取，不是防 XSS 的安全边界。
- 未登录访问管理页面后，登录成功返回原站内有效路由；无目标则进入管理端账号页。不允许任意外部回跳。
- 多个请求同时认证失效时，统一清除登录状态，只提示一次并跳转登录页。保留目标路由，不保存密码或未提交表单，不自动重放新增/修改请求。
- 首版退出为本地退出：清除令牌、当前账号与页面数据并返回登录页。不调用 C 端退出接口，不宣称服务端令牌已撤销。

## 已确认：恢复、失败与计时

用户对第二轮三项推荐回复「不错 继续」：

- 刷新后有令牌时先请求当前账号信息，成功后加载业务页面，期间显示加载状态。认证失效回登录页；网络或服务端异常保留令牌，提供重试与返回登录，不误判为会话失效。
- 登录表单只含手机号、密码、登录按钮；无验证码、注册和找回密码。支持回车、防重复提交；失败时保留当前表单输入，密码不持久化、不写日志，离开登录页清除。登录接口自身错误留在表单，不触发会话过期跳转。
- 不做前端倒计时退出，不轮询续期，以服务端认证结果为准。旧会话请求不得覆盖或清除新会话状态。

## Resolution

用户对 Q8 及此前全部设计确认回复「yes」，本议题正式解决并关闭：

- **存储与会话**：`accessToken` 存储于 `sessionStorage`，支持当前标签页刷新后恢复；首版不提供「记住我」。该存储仅用于客户端状态维持，不是防 XSS 的安全边界。
- **登录交互与校验**：登录表单仅包含手机号、密码、登录按钮，无验证码、注册或找回密码。支持回车提交与防重复提交机制；失败时保留输入以便修正，密码不持久化、不写日志，离开登录页即清除。
- **密码传输兼容**：基于对 `/Users/lien/prj/Framework-Java` 的只读核查，密码以 AES-128/ECB/PKCS5Padding 加密并输出为 Hex 字符串提交，手机号直接以明文提交。明确该加密仅为兼容既有后端契约，不提供可靠保密性，不替代 HTTPS，不在文档或日志中记录密钥。
- **状态恢复与并发 401**：刷新后若存在令牌，必须先调用 `GET /sys_user/login/get_info` 恢复管理端账号，成功后再加载业务页面；网络或服务端异常时保留令牌并允许重试，不误判为会话失效。多个请求同时返回 401 时，统一清除本地状态，只弹出一次提示并重定向至登录页，记录原有效站内路由，不自动重放写操作。
- **退出与未验证边界**：因后端无管理端主动退出接口与前端刷新接口，首版仅实现本地退出（清除 sessionStorage、当前账号并回跳登录页），不宣称服务端令牌已失效。实际网关地址、CORS、登录白名单与 Java/JS 加密互操作测试交由后续联调与部署议题核实。
