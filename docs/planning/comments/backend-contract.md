# 确认首版业务范围与浏览器可用接口 — 讨论记录

## 用户确认：首轮范围取舍

- 本项目是个人学习仓库，首版优先完成功能；安全加固与生产上线安全验收不作为本轮范围决策的阻塞条件。这不代表接口已经安全，也不代表可以取消现有认证。实际路由、跨域、可达性等功能事实仍须核实。
- 首版不纳入 C 端用户管理。
- 管理端账号保留列表、筛选、新增；不纳入编辑、重置密码与停用。不提交占位密码绕过编辑校验。

本轮记录时字典与参数的操作范围尚待确认；最终结果见下方 Resolution。

## 实际数据库核验：账号候选字典

用户提供数据库连接后，通过只读事务核验目标数据库（库名已脱敏）的 `sys_dictionary_type` 与 `sys_dictionary_data`；未查询账号表，未修改数据。连接凭据不记录到仓库。

| 用途 | type_key | data_key | value |
| --- | --- | --- | --- |
| 身份候选 | admin | platform_admin | 平台管理员 |
| 身份候选 | admin | super_admin | 超级管理员 |
| 状态候选 | common_status | disable | 停用 |
| 状态候选 | common_status | enable | 启用 |

上述类型及字典项的 `status` 均为数值 `1`，字典项 `sort` 均为 `1`。字典记录的数值状态与账号使用的字符串状态编码是不同字段，不混用。

更正先前判断：仓库未提供初始化数据不代表实际环境缺少数据；该库已有上述字典，不需要为当前环境另造编码或补初始化。源码未绑定身份/状态的 typeKey，前端采用上述类型属于基于实际数据提出的映射，仍待范围讨论确认；尚未据此验证浏览器网关访问。

核验查询（只读事务内）：

```sql
SELECT type_key, value, status
FROM sys_dictionary_type
WHERE type_key IN ('admin', 'common_status')
ORDER BY type_key;

SELECT type_key, data_key, value, sort, status
FROM sys_dictionary_data
WHERE type_key IN ('admin', 'common_status')
ORDER BY type_key, sort, data_key;
```

用户允许继续只读核对数据库事实；后续按问题所需查表结构及最小必要字段，避免无关数据与敏感字段输出。

## Resolution

用户已确认本议题的范围取舍：

- 首版按个人学习项目推进，功能优先，不改后端；安全加固不阻塞规划，但不宣称未经验证的接口安全或已可达。
- 保留登录、当前账号信息，以及地图原定的布局、静态导航和错误页。
- 管理端账号：列表、精确筛选、新增；列表按后端非分页契约处理。不做编辑、重置密码、停用或删除。
- 字典类型、字典项、参数：列表、筛选、分页、新增、编辑；不做删除，编辑时编码只读。字典项从所属类型进入管理，不更换所属类型。
- 不纳入 C 端用户管理，不以内部 Feign 用户接口补齐页面能力。
- 账号候选字典以实际数据库为事实来源，当前环境已有所需数据，不新造编码或要求重复初始化。具体编码见上方实库核验；通过字典管理列表读取候选，不把内部 Feign 查询接口当浏览器入口。

接口路径、字段、校验、VO、分页及错误码证据见[首版后端候选契约交接](../assets/backend-contract.md)。该资产是源码契约与只读数据核验，不是浏览器联调通过报告。
