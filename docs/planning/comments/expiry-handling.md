# 统一认证失效与旧会话隔离

## Resolution

已交付统一认证失效与旧会话隔离机制及完整页面级测试：

- 在 `src/api/client.ts` 引入基于单调递增 `sessionSeq` 的会话版本控制与请求级元数据（`metadata.sessionSeq`），以及并发安全的 `setSessionExpiredHandler` / `triggerSessionExpired` 统一 401 触发机制。
- 对当前会话的并发 401，仅触发一次会话清理、跳转与提示：清空本地会话存储与 Pinia 状态，向登录页回跳并传递受保护路由重定向目标，在登录页呈现单一 `[role="alert"]` 提示「登录状态已失效，请重新输入」。
- 严格隔离旧会话请求：通过校验请求元数据中的 `sessionSeq` 与全局当前会话版本，若请求来自旧会话，其迟到响应（无论是 200 成功还是 401/网络异常失败）均被隔离，不得覆盖新登录账号或清除新会话；登出后的迟到响应绝不恢复旧会话。
- 区分登录接口自身的错误与会话过期：`/sys_user/login/password` 的 401/400 留在登录表单并保留工作人员输入的手机号与密码，仅展示单次表单错误「手机号或密码错误，请检查后重试」，不触发会话过期或重定向。
- 统一分类其他请求失败（网络错误 `network`、HTTP 状态异常 `http`、业务错误码异常 `business`），同一次失败仅反馈一次。
- 新增页面级与接口级测试 `tests/expiry-handling.test.ts`，涵盖并发 401 统一收敛、登出后迟到响应隔离、切换账号后旧响应隔离、登录接口自身 401 错误保留与分类错误断言 6 项场景。

自动检查已全数通过：`npm run check`（含 Prettier 格式校验、ESLint 零警告、vue-tsc 严格类型检查、Vitest 测试及 Vite 构建）。
