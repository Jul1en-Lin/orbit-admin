# 刷新后自动恢复会话

## Resolution

已交付刷新后自动恢复当前管理端账号的完整链路与页面级测试：

- 在 `src/auth/store.ts` 补齐 `restoreSession` 动作与并发防重复（`inFlightRestore`），保留 `restoreAttempted` 与 `restoreError` 状态；在退出（`signOut`）与测试重置时彻底清理。
- 在 `src/router/index.ts` 的全局路由守卫中，对携带令牌访问受保护路由的初次导航自动触发会话恢复；恢复执行期间在 `App.vue` 展示居中加载状态（`role="status"`），拦截业务页面（如工作台）的渲染。
- 当恢复请求成功时，填充当前管理端账号并直接放行至目标受保护页面；当遇到网络故障或服务端异常（如 500、503）时，保留 `sessionStorage` 中的令牌不清理，重定向至登录页并提供「重试确认账号」与「返回登录」入口及对应错误反馈。
- 当遇到真正认证失效（HTTP 401）时，彻底清理本地会话存储与令牌，重定向至登录页并切换为常规登录表单，展示单一失效提示「登录状态已失效，请重新输入」。
- 新增页面级测试 `tests/session-restore.test.ts`，覆盖加载状态门禁、恢复成功直达、服务端异常保留与重试、放弃返回常规登录、网络故障及 401 真正失效清理 5 项关键场景；现有登录测试与测试框架均保持全绿。

自动检查已全数通过：`npm run check`（含 Prettier 格式、ESLint 零警告、vue-tsc 严格类型检查、Vitest 测试及 Vite 构建）。
