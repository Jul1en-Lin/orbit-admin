### 维度三：独立部署链路与生产静态托管配置
- **验收结论**：**【已验证】**
- **核验依据与配置事实**：
  1. **同源代理与认证头**：前端 Axios 请求基径统一为同源 `/api`，拦截器统一注入 `Authorization: Bearer <accessToken>`；Vite 开发代理与生产 Nginx 均重写 `/api/` 为 `/admin/`，前端代码不硬编码微服务端口。
  2. **SPA History 路由回退**：`deploy/nginx/orbit-admin.conf` 配置 `location / { try_files $uri $uri/ /index.html; }`，深层业务路径（`/accounts`, `/dictionaries`, `/parameters`, `/workbench`）直接刷新不报 404；入口 HTML 显式禁用强缓存。
  3. **静态资源 404 隔离与强缓存**：`location ^~ /assets/` 配置 `try_files $uri =404;` 与 1 年 `immutable` 强缓存；构建产物哈希变化时自动更新；缺失的 JS/CSS 产物直接返回 HTTP 404，绝不回退至 `index.html`，彻底避免 HTML 作为脚本执行的 MIME 解析错误。
  4. **API 错误透传**：`location ^~ /api/` 配置 `proxy_pass` 与 `proxy_intercept_errors off`，后端微服务返回的 400、401、500 等业务与鉴权错误完整透传至前端统一处理，不被 Nginx 截胡改写。

## 4. 授权边界与安全交付要求

为防范生产事故与越权操作，特此明确如下授权边界：

1. **共享基础设施保护**：未获明确书面授权前，严禁变更后端微服务配置、Nacos 配置中心、网关路由策略或公共中间件拓扑。
2. **数据库破坏性清理禁令**：未获明确授权前，严禁在共享数据库上执行任何 `DROP TABLE`、`TRUNCATE` 或破坏性批量 `DELETE` 操作；必须使用约定的前缀（如 `test_`）隔离测试数据。
3. **生产发布授权禁令**：未获正式授权与安全评审前，严禁擅自将前端构建产物（`dist`）发布或上传至生产 Nginx 节点或公开网络提供服务。
4. **凭据保密原则**：前端脚手架源码、配置文件及自动化测试用例严禁硬编码任何真实服务端机密、数据库密码或私钥证书。
5. **规格与地图关闭约束**：**父规格（`11-first-release-spec.md`）与地图的关闭由用户决定，本票不代为处理**。

## 5. 待真实后端与凭据具备后的端到端验证 Runbook

当维护者获准提供完整微服务运行环境与合法测试账号凭据后，请依循以下 Runbook 执行真实端到端验收：

### 阶段一：后端依赖与微服务栈启动
1. 启动 MySQL（3306），运行 SQL 脚本初始化 `sys_user`、`sys_dictionary_type`、`sys_dictionary_data`、`sys_argument` 数据表结构与基础字典数据。
2. 启动 Redis（6379）及 Nacos（8848）服务。
3. 启动本地 API 网关 `lien-gateway`（18080）与后台微服务 `lien-admin`（18081）。
4. 验证端口监听状态：
   ```bash
   lsof -i :18080
   lsof -i :18081
   ```

### 阶段二：测试数据与凭据准备
1. 准备一个在数据库中处于启用状态的管理员账号（手机号与明文密码，例如 `13800138000` / `password123`）。
2. 准备用于测试新增与编辑的前缀数据（建议统一采用 `TEST_` 或 `demo_` 前缀）。

### 阶段三：端到端功能验证操作规程
1. **登录与会话恢复**：
   - 打开浏览器访问前端应用，输入管理员手机号与密码，按 Enter 或点击登录；
   - 抓包核实：密码经过 AES 加密传输，网关放行，成功获取 `accessToken` 并跳转至工作台就绪页；
   - 刷新页面：核查页面出现短期加载状态后自动发起 `GET /api/sys_user/login/get_info` 并成功恢复当前管理端账号昵称；
   - 点击顶栏「退出」：核实会话注销，本地令牌清理，页面跳回登录页。
2. **管理端账号查询与新增**：
   - 访问 `/accounts` 页面，核查列表正常展示，身份与状态字典准确映射为中文标签；
   - 输入手机号进行精确筛选，验证查询结果与重置恢复；
   - 点击「+ 新增账号」打开弹窗，输入重复手机号提交，核实服务端 400 校验提示保留输入；
   - 输入全新合法账号提交，验证成功关闭弹窗并自动刷新列表。
3. **字典类型与字典项维护**：
   - 访问 `/dictionaries` 页面，验证字典类型分页与前缀筛选；
   - 新增测试字典类型并进入其「维护字典项」页面；
   - 验证字典项分页、只读编码锁定、新增字典项及编辑更新生效。
4. **参数维护与可选筛选核验点实测**：
   - 访问 `/parameters` 页面；
   - **核心实测点**：在不输入任何参数键名与名称筛选条件的情况下直接点击「查询」，核实服务端是否报 400 校验异常（实测后端缺少 `@Validated` 时的真实行为）；
   - 新增多行文本参数，验证换行符原样提交与列表展示；编辑参数值并验证成功保存。
5. **异常与认证失效流程实测**：
   - 打开任意新增弹窗并输入脏数据，在开发者工具中篡改 `sessionStorage` 伪造失效令牌；
   - 触发一次查询或保存，核实前端拦截 401 错误，立即关闭弹窗并清空脏表单，单次提示失效后跳转至登录页，且绝不自动重放写操作。

### 阶段四：生产部署与线上验收
1. 将 `dist` 部署至 Nginx 静态根目录，应用 `deploy/nginx/orbit-admin.conf` 配置；
2. 实测在 `/accounts`、`/dictionaries`、`/parameters` 路径下直接进行浏览器硬刷新，验证 Nginx 200 返回与 SPA 路由正常恢复；
3. 实测故意访问 `/assets/non-existent.js`，验证 Nginx 严格返回 HTTP 404（不回退至 `index.html`）；
4. 云端配置 upstream 与正式域名、安装 SSL/TLS 证书后，实测 HTTPS 握手与端到端网络通信。
