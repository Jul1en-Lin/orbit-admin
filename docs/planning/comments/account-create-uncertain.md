# 写入结果不确定与刷新失败

## Resolution

已落实新增管理端账号在写入结果不确定（如请求超时、网络中断、取消）以及写入成功但列表刷新失败时的反馈边界与防误操作保护：

- 写入结果不确定（超时 / 网络中断 / 取消）：
  - 在 `src/api/client.ts` 中扩展 `ApiError`，准确识别超时（`code === 'ECONNABORTED' | 'ETIMEDOUT'` 或包含超时特征）与取消/中断异常，并将其归类为 `'timeout'`。
  - 在 `src/views/AccountListView.vue` 中建立写入不确定性检测（`isUncertainWriteError`）。
  - 当发生超时或中断等无法确认服务端是否已落库的异常时：
    * **完整保留已填表单项**（身份、手机号、密码、昵称、状态、备注等），不重置表单；
    * **解除提交锁定**：恢复 `createSubmitting = false`，确认新增按键与所有表单输入字段恢复可操作；
    * **展示明确警示文案**：提示「提交结果未确认，请先查询核实」（通过 `data-test="create-error-message"` 与 `data-test="create-uncertain-warning"` 支持）；
    * **绝不发起自动重试**，严格将 POST 请求调用次数约束为单次；不向工作人员虚假承诺前端绝对防重复写入，引导工作人员先查询核实。
    * 支持工作人员手动关闭弹窗前往列表筛选核实，再次打开弹窗时正常重置表单。
- 写入成功但列表刷新失败：
  - 当 `createAccount` 成功但后续的 `loadAccounts` 抛出异常或失败时：
    * **立即关闭新增弹窗并清空已填表单**（因为账号已确实写入服务端数据库，防止工作人员再次误点击保存造成重复写入）；
    * **分别清晰说明两项事实**：在页面顶部展示明确提示横幅（`data-test="create-refresh-warning"` / `data-test="refresh-failure-notice"`），文案明确为「账号创建成功，但列表刷新失败。请通过下方表格重试刷新查看最新数据，无需重复提交保存。」，既告知新增已成功，又说明列表刷新失败，明确告知无需重复提交保存；
    * **表格呈现错误重试状态**：表格区域正常展示错误状态（`data-test="state-error"`）及重试按钮（`data-test="state-retry"`）；
    * **支持重试与手动关闭**：工作人员点击表格的「重试」重新获取列表成功后，自动清理刷新失败提示横幅；工作人员亦可点击「知道了」手动关闭该横幅。
- 自动化测试与质量保障：
  - 新增 `tests/account-create-uncertain.test.ts`，涵盖：
    * 请求超时场景：保留表单字段、解除提交锁、展示「提交结果未确认，请先查询核实」、无自动重试、无绝对幂等宣称；
    * 请求中断/断开场景：保留表单字段、解锁表单并展示核实提示；
    * 提示后操作流程：工作人员关闭弹窗后手动查询、重新打开弹窗展示空白表单；
    * 写入成功但刷新失败场景：关闭弹窗、清空表单、两项结果分别提示、避免诱导重复保存；
    * 表格重试恢复场景：点击重试成功刷新列表并自动消除横幅；
    * 手动关闭横幅场景：点击「知道了」关闭横幅。
  - 全套代码与测试质量检查全部通过：`npm run check`（Prettier 格式检查、ESLint 零警告、vue-tsc 严格类型检查、Vitest 71 项测试全数通过、Vite 生产构建成功）。
