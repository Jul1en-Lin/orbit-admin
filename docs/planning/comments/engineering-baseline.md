# 确定首版工程工具与质量门槛：讨论记录

## Resolution

用户逐轮确认并最终同意以下结论，关闭[确定首版工程工具与质量门槛](../issues/05-engineering.md)。本议题仅作规划，不安装依赖、不实施工程或配置流水线。

### 运行时与版本管理

- 采用 Node 24 + pnpm。实现时核实与 Vue/Vite 等依赖的兼容性，填写 Node 具体补丁版本，并通过 `packageManager` 固定 pnpm 版本。
- 提交 `pnpm-lock.yaml`；验收采用冻结锁文件安装，保证依赖安装可复现。
- 依赖升级单独进行，升级后重跑检查；不追随每次最新发布，不配置自动依赖升级机器人。

### 静态检查

- TypeScript 开启 strict，使用 vue-tsc 检查类型。
- 使用 ESLint 和 Prettier；类型、Lint（零警告）、格式检查与生产构建均必须通过。
- 不建设复杂自定义规则。

### 自动化测试

- 使用 Vitest + Vue Test Utils + jsdom，选择“关键逻辑与交互自动化、完整业务流程人工验收”。
- 优先覆盖会话恢复、并发 401 的统一处理、安全站内回跳、不重放写请求、接口数据转换。
- 关键表单交互覆盖校验、提交成功与失败、避免重复提交。
- 登录加密使用 Java 侧可信样例校验兼容性；样例在实现阶段准备，本次未完成互操作验证。
- 不设置覆盖率百分比，不重复测试 Element Plus 内部实现，不引入大面积快照测试、完整模拟后端或浏览器端到端自动化。

### 验收门槛

首版交付须通过两层验收：

1. **自动检查**：提供一个本地统一命令，执行格式检查、Lint、类型检查、测试与生产构建。日常改动运行相关检查，首版交接运行完整检查。
2. **人工验收**：真实后端登录与会话失效、首版页面动作、主题与浮层、关键键盘路径、窄视口内容可达性。已有组件选型议题约定的首批真实组件验收继续有效。

后端环境不可用或行为尚未验证时，标记“未验收”，不以模拟测试结果替代真实联调通过。构建成功不等于首版可交付。网关、跨域、环境接入与部署配置继续由[确定前端独立部署与环境配置边界](../issues/06-deployment.md)处理。

### 浏览器范围

- 首版验收目标为桌面 Chrome、Edge 当前稳定版；交接时记录实际验收版本。
- Firefox、Safari 暂不作为首版验收目标，不承诺移动端适配。
- 基础窄视口可用性不等于建设专门移动端体验。

### 暂不建设与执行边界

- 不建设 Git hooks、commitlint、远程 CI 或自动发布。
- 本地统一检查属于交接时必须执行的约定，不宣称存在服务端强制拦截。
- 具体工具版本和脚本配置留给实现阶段；页面逐项验收规格仍需结合真实契约与视觉验证细化。
