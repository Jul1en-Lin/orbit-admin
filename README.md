# Orbit Admin

面向 B 端管理场景的独立纯静态管理端脚手架。

开箱即用交付统一登录鉴权、会话持久化与刷新恢复治理、受保护路由守卫及基础管理模块。下游业务可直接复制代码库独立演进，天然适配纯静态 Nginx 托管与同源网关代理。

## 模块结构

系统按公共基础底座与核心业务功能解耦分层，采用统一网络契约与响应式状态中枢驱动：

- 在 `api/` 模块中声明标准化业务请求契约与数据模型，由统一网络客户端完成信封解包。
- 在 `views/` 模块中通过响应式组合式 API 驱动页面渲染，具备竞态消除与脏表单防护机制。

```
src/
  api/            # Axios 客户端封装与业务 API 契约声明
  auth/           # Pinia 用户状态管理与 CryptoJS 密码加密
  router/         # Vue Router 实例配置与受保护路由拦截守卫
  views/          # 登录、工作台、账号、字典、参数与 404 视图
  components/     # AppShell 布局骨架、毛玻璃顶栏与主导航
  styles/         # 深墨绿设计规范与 Element Plus 主题定制
  main.ts         # 应用入口、组件全局注册与根实例挂载
vite.config.ts    # 开发构建与反向代理跨域配置
.env.*            # 开发、预发布与生产多环境变量配置
deploy/nginx/     # 纯静态托管部署与同源反向代理网关配置
```

## 核心业务功能

### 登录与认证

账号登录和初始化会话流程。

- **密码加密传输**：提交前使用 AES 对称加密密码，与后端解密逻辑对齐，避免明文在链路中传输。
- **重定向地址过滤**：登录成功后跳转到来源页面时，只允许站内相对路径，过滤双斜杠等异常地址，防止跳往外部钓鱼站点。
- **提交防重与状态复位**：登录请求期间锁定按钮，防止连击重复提交；请求返回或发生异常后均能复位加载状态，并给出对应提示。

### 用户管理

账号维护与操作防护。

- **数据提交与刷新分离**：数据保存成功但后续自动刷新列表失败时，主动提示已保存成功并打断操作，避免误判重复提交。
- **查询序号防乱序**：进行检索和分页查询时携带唯一自增序号，只采用最新发出的请求响应，丢弃迟到的旧响应，避免慢请求覆盖快请求。

### 字典管理

维护通用业务标签。

- **类型与字典项分层**：按类型与数据值两层维护，支持从类型列表下钻配置具体枚举项。
- **表单交互对齐**：结合后端字段约束，在前端校验拦截非法清空等操作，避免产生无意义的报错请求。

### 参数设置

全局参数热刷新。

- **拦截校验**：校验并拦截纯空格内容，避免写入空配置引发微服务解析异常。
- **运行时即时生效**：直连微服务参数接口保存配置，微服务读取后即时更新，无需重启。
- **原生格式支持**：配置框支持原始缩进和换行，支持 JSON、规则串与长文本内容的存储。

## 基础组件库

### 网络请求封装

- **统一信封解包**：拦截器自动校验业务状态码，正常时直接解出数据对象交给业务层，简化调用方逻辑。
- **错误分类处理**：统一捕获业务未通过、HTTP 状态错误、接口超时和网络中断等四类异常，输出格式化的错误信息。

### 会话恢复与持久化

- **状态持久化同步**：在状态仓库中维护 Token 与用户信息，同步到浏览器本地存储。
- **并发恢复去重**：页面刷新或路由拦截同时触发会话恢复时，合并复用同一个在途 Promise，避免重复请求个人信息接口。

### 路由拦截与权限控制

- **已登录防重跳**：已处于登录状态的用户访问登录页时，自动跳往工作台，避免重复登录。
- **受保护路由拦截**：页面配置鉴权标记后，未登录用户访问会被拦截并导向登录页，同时记录来源地址用于登录后回跳。

### 工程规范与格式化

- **自动化校验**：配置格式检查与一键修复脚本，与 ESLint 协同保证提交代码的整洁一致。
- **统一代码风格**：通过 Prettier 约束单引号、无分号与行宽等排版规则，避免多人协作时产生无意义的格式差异与 Git 冲突。

### 静态部署与反向代理

- **网关反向代理**：统一将 `/api` 代理到后端网关，开发环境与生产环境均无需额外处理浏览器跨域限制。
- **路由回退**：Nginx 配置所有路径回退到入口文件，入口 HTML 设置不缓存，保证发版后及时拿到新资源。

## 快速开始

### 环境准备

项目依赖 Node.js `24.15.0` 与 pnpm `12.4.2`（推荐通过 Corepack 启用）：

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

开发服务器默认运行在 `http://localhost:18000`。

### 代理与环境配置

浏览器端统一通过同源 `/api` 发起请求，Vite 开发代理将其重写为 `/admin` 转发至本地网关。默认目标为 `http://127.0.0.1:18080`。

若需调整网关地址，复制 `.env.example` 为 `.env.local` 并配置：

```ini
VITE_GATEWAY_TARGET=http://127.0.0.1:18080
```

> **注意**：网关目标仅在代理层进行调度，前端应用面向同源 `/api`，绝不直接访问各业务微服务。

## 质量检查

运行项目统一质量门禁检查：

```sh
corepack pnpm run check
```

该命令将依次严格执行：

1. `pnpm run format:check`：Prettier 代码格式检查
2. `pnpm run lint`：ESLint 静态规则分析（零警告）
3. `pnpm run typecheck`：vue-tsc 严格类型检查
4. `pnpm run test`：Vitest 自动化测试套件
5. `pnpm run build`：生产环境打包构建

单独执行子命令：

- `corepack pnpm test`：运行自动化测试
- `corepack pnpm typecheck`：执行类型检查
- `corepack pnpm build`：打包生产产物至 `dist/`

## 模板复用与独立演进

Orbit Admin 是标准的纯静态前端工程脚手架：

- **无私有 CLI 工具**：使用标准 pnpm 工具链。

## 生产构建与 Nginx 部署

执行构建命令生成生产静态资源：

```sh
corepack pnpm build
```

产物输出至 `dist/` 目录。生产环境部署推荐使用 Nginx 作为统一反向代理与静态托管服务，核心配置文件位于：

- `deploy/nginx/orbit-admin.conf`：虚拟主机站点配置（推荐置于 `/etc/nginx/conf.d/`）
- `deploy/nginx.conf`：单机或容器化完整主配置文件示例

**核心部署策略**：

1. **History 模式路由回退**：`location /` 中配置 `try_files $uri $uri/ /index.html`，同时入口 HTML 禁用强缓存。
2. **静态资源 404 隔离**：`location ^~ /assets/` 配置 `try_files $uri =404` 与 1 年 `immutable` 强缓存。缺失文件必须直接 404，绝不回退至 `index.html`。
3. **API 代理与错误透传**：`location ^~ /api/` 配置 `proxy_pass http://gateway_upstream/admin/;` 且 `proxy_intercept_errors off;`，确保网关错误原样透传。

完整生产配置与部署指导详见 [部署与使用说明 (docs/deployment.md)](docs/deployment.md)。
